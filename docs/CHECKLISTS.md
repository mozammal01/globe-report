## Security

| Item                                                                          | Status | Notes                                                                                                                                                                                                                                                                                                      |
| ----------------------------------------------------------------------------- | ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Every admin mutation checks `getCurrentAdmin()`                               | ✅     | Verified across all `lib/actions/admin/*.ts`                                                                                                                                                                                                                                                               |
| Every user mutation derives identity from session, never a client-supplied id | ✅     | Bookmarks, profile, history — no IDOR found                                                                                                                                                                                                                                                                |
| File upload auth enforced at the actual write path                            | ✅     | **Fixed a real gap**: the shared upload helper was exported from a `"use server"` module, making it independently callable (bypassing `uploadMedia`'s admin check) with an attacker-chosen `uploadedById`. Moved to a plain server-only module so only the two auth-checked wrapper actions are reachable. |
| Open-redirect protection on post-login redirect                               | ✅     | **Fixed**: `redirectTo` query param is now validated as a same-origin relative path before `router.push()`                                                                                                                                                                                                 |
| `dangerouslySetInnerHTML` only renders sanitized content                      | ✅     | Article HTML sanitized via a strict DOMPurify allowlist at write time; JSON-LD renders server-constructed data, not user input                                                                                                                                                                             |
| Rate limiting on public mutation endpoints                                    | ✅     | **Added**: in-memory per-IP/per-user limiter on newsletter subscribe, contact submit, search, bookmark toggle, and view tracking. Documented as single-instance-only — see Roadmap for the multi-instance upgrade path.                                                                                    |
| View-count / trending manipulation resistance                                 | ✅     | **Added**: server-side dedup (same IP + article within 30 min is not double-counted), on top of the new rate limit                                                                                                                                                                                         |
| Environment secrets never leak to the client bundle                           | ✅     | `clientEnv` only exposes `NEXT_PUBLIC_SITE_URL`                                                                                                                                                                                                                                                            |
| Mutating GET routes resistant to prefetch/scanner triggering                  | ⚠️     | `/newsletter/confirm` and `/newsletter/unsubscribe` mutate on render from a `searchParams.token` GET — low real-world risk (single-purpose random token, idempotent outcome) but not best practice; documented in Roadmap as a candidate for a POST-confirmation click in a future pass                    |
| Unused RBAC roles don't silently grant access                                 | ✅     | `EDITOR`/`AUTHOR` roles exist in the schema/UI copy but are not wired to any access-control branch — confirmed they're inert, not a hidden backdoor; genuinely unused, tracked in Roadmap as future editorial-workflow scope                                                                               |
